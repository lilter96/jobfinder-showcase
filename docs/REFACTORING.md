### Atomic scrape operational state and shared request windows — 2026-10-04 (release still open)

- Remaining-writer audit found `ScrapeStateStore` saving pause and streak/budget through separate generic commits, with a process-local saved-pause dictionary and ten-second cached reads. An old producer could overwrite another producer's request list, successful recovery never removed the persisted pause, and malformed state silently reset to an empty budget. This is a confirmed code gap, not a claim of a reproduced production block.
- The production store now implements `IScrapeRequestLedger` with one PostgreSQL family lock. Compatible legacy projections are read without mutation and imported on the first actual transition; owned JSON/revision and compatible pause/budget rows publish atomically. Owner/version/value/time/materialization checks fail closed. Generic namespace Set/Remove and old whole-snapshot Save refuse. Ordinary unbudgeted successful crawl hosts do not create state rows.
- `PoliteHttp` reads fresh pauses and reserves every direct/proxy attempt before the wire. Independent producers share exact persisted windows; local standard window limiters/pacing and Polly remain. Background has its own persisted share, High bypasses counts but not active pause, denied admission writes nothing, and proxy fallback cannot exceed the same budget. Bounded quota waiting uses the original deadline/cancellation outside the HTTP timeout. Failed reservation commits no state and performs no network call.
- Block/recovery projection and native notice commit together; active repeated block publication creates one notice. Successful completion carries its original block revision and cannot clear a newer pause even after expiry. Polly half-open retries use the owned streak instead of adding its half-open count twice. `Announced` means notice admitted, not delivered; job/hh-link adapters do not add a second alert. Reserved-but-interrupted requests can conservatively occupy budget; this does not promise exactly-once HTTP, response+SQL atomicity or cross-process random pacing.
